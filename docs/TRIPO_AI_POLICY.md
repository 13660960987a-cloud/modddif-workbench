# Tripo P2.0：AI 调用决策与执行约束

用途：供操作映纹工坊的 AI 在提交 Tripo 任务前读取。本文件是决策规范，不是已经接通的 API 客户端。不能把阅读本文当成生成授权，也不能把 API 成功当成美术验收通过。

## 1. 密钥与入口

- 本机配置文件：`~/Downloads/.env`。
- 已确认存在字段 `TRIPO_API_KEY`、`TRIPO_BASE_URL`，不在此文件记录字段值。
- 只允许本地后端读取密钥并构造 Authorization。禁止把密钥放进网页、浏览器请求参数、命令行参数、日志、报告、任务记录、Git 或截图。
- API v3 官方入口：`https://openapi.tripo3d.com/v3`。执行端必须校验目标域名与 HTTPS，禁止跟随带鉴权请求的重定向，禁止把密钥发送给返回的模型下载 URL。
- 默认先输出 dry-run 决策计划；获得本次任务或明确限定的批次额度授权后才提交付费任务。不能因为找到密钥就调用。

## 2. 已核对的官方参数

文档来源：
- https://developers.tripo3d.com/llms-full.txt
- https://developers.tripo3d.com/en/docs/generation-image-to-model/p
- https://developers.tripo3d.com/en/docs/mesh-uv
- https://developers.tripo3d.com/en/docs/mesh-segment

当前 P2 模型 ID：`P2-20260801`。不要把产品名 `P2.0` 直接当 API model 值。

图生模型：`POST /generation/image-to-model`。
- `input`：上传文件得到的 file_token、图片 URL 或适用的任务 ID，三者选一。
- PNG/JPEG/WebP，最大 20MB，建议至少 256×256。
- `quad:false`：请求面数范围 48–50000。
- `quad:true`：请求面数范围 48–25000。
- 省略 `face_limit` 表示服务端自适应；需要项目预算可控时明确填写。
- `texture:true,pbr:true` 用于带 PBR 材质输出。
- `orientation:"align_image"` 在开启 texture 时用于对齐输入视角，不代表一定得到正确正脸。
- 计划后处理时不要提前指定 export_orientation；最终导出再转换朝向。

注意：50000 个三角面和 25000 个四边面约为相同的等价三角面预算，不能宣称三角路线必然有两倍几何细节。请求 face_limit 与实际输出统计可能有偏差，必须测量最终文件。

## 3. AI 如何选择拓扑和面数

先看参考图，并记录：用途、最近观看距离、轮廓复杂程度、关键区域（脸/手/雕刻/武器刃口）、是否变形、是否需要编辑部件、运行平台限制。不能仅按图片像素或物体名称决定。

以下是工作台的建议档位，不是 Tripo 的质量保证：

| 资产需求 | 优先选择 | 建议请求面数 |
|---|---|---|
| 远景、简单小道具，轮廓简单 | 三角面 | 2000–8000 |
| 普通中景道具 | 三角面 | 8000–20000 |
| 近景武器、复杂装饰、雕刻 | 三角面 | 20000–35000 |
| 主角级展示、脸部/龙头特写、复杂镂空 | 三角面 | 35000–50000 |
| 明确要后续 DCC 编辑、细分或四边面工作流 | 四边面 | 5000–25000，按复杂度选择 |

决策原则：
1. 默认静态游戏资产用三角面；不要无条件全拉最大。
2. 有明确四边面编辑需求才选四边面；四边面不保证动画拓扑、面部边流或绑定质量。
3. 脸部特写优先保证眼鼻嘴轮廓和 UV 密度；提高整模面数不等于脸部会正确。
4. 需要可编辑部件时优先三角面路线，并提前评估分件阶段。不要把材质槽数等同于部件数。
5. 用户给了平台/面数预算时优先遵守；需求不明确时做保守计划，记录假设，不能擅自用最高成本。
6. 保留四边面时核对实际输出格式和 DCC 中面类型；GLB 会三角化，不可用 GLB 证明保留四边面。

## 4. 分部件：不要混用不同模型的参数

用户希望三角面 P2 输出可分部件。当前官方 P-Series 图生模型章节未列出 `generate_parts`，而 H-Series 章节列出了它；这不足以证明 P2 接受该参数。

因此默认安全路线：
**P2 三角面生成 → 保存原输出 → 独立 mesh segmentation 后处理 → 检查部件 → 必要时 Smart UV。**

分件接口为 `POST /mesh/segment`。执行时必须先阅读该接口当时的 schema、支持模型版本、输入格式、费用和贴图保留规则，再构造请求；不要凭此文件猜分件 body。

只有当 P2 对应的当前 schema 或供应商确认明确支持 `generate_parts` 时，才启用生成时分件。不要为了试参数自动发起付费探测。

H-Series 的已知限制不能直接照搬成 P2 支持证据：生成分件要求 texture=false、pbr=false；quad=true 会被忽略，smart_low_poly=true 会让分件不产生。若未来 P2 明确支持，也必须复核 P2 自身的兼容规则，不能与带纹理 PBR 参数盲目组合。

分件验收：检查是否独立 mesh、关键小部件是否丢失、交界处是否破洞、法线与材质是否保留；检查实际网格而不只看任务 success。

## 5. Smart UV 决策

接口：`POST /mesh/uv`。
请求示例：
```json
{"input":"成功生成任务的 task_id","model":"default","bake":true}
```

- 输入不能超过 **80000 等价三角面**，一个四边面算两个三角面。多部件求总和；不要只拿请求面数判断。
- 官方文档当前列出每次 20 credits；实际执行时重新核对费用。
- 有原纹理且希望保留时 bake=true；明确只要 UV、没有原纹理时才考虑 false。
- 返回 UV 预览不代表 UV 合格：检查重叠、拉伸、脸部像素密度、接缝位置和部件间面积比例。
- 超过上限先制定降面方案，不盲发 UV 任务；降面可能损伤特写结构，需要再次验收。
- 保存 UV 前原模型与所有原贴图。历史实测 Smart UV 可能把高分辨率贴图降到 2K，不能承诺保留 4K/8K。
- UV 改变后禁止直接将新贴图覆盖到旧 UV 模型。必须同时使用新 UV 模型，或经过验证的贴图转移流程。
- 若分件会改变几何/UV，通常先分件再做最终 UV；每步之后检查实际输出，而不是重复无条件 UV。

## 6. 提交前输出机器可读计划

```json
{
  "schemaVersion": 1,
  "mode": "dry-run",
  "asset": "示例：近景雕刻柱",
  "model": "P2-20260801",
  "topology": "triangles",
  "faceLimit": 40000,
  "reason": "用于近景，脸部和镂空轮廓复杂；没有四边面编辑需求",
  "criticalRegions": ["龙头眼鼻嘴", "镂空边缘"],
  "generation": {"quad": false, "texture": true, "pbr": true},
  "parts": {"required": true, "route": "postprocess-segment", "schemaVerified": false},
  "smartUV": {"enabled": true, "bake": true, "maxEquivalentTriangles": 80000},
  "approvalRequired": true,
  "costCredits": null,
  "status": "待核对分件参数和总费用，未提交"
}
```

不要把整个计划原样发给 API；只提取对应端点支持的字段。costCredits=null 表示未知，不是免费。最终计划必须列出每项付费步骤、数量、预算上限及输出目录。

## 7. 执行状态和失败恢复

- 上传 → 提交一次 → 立即持久化 task_id → GET /tasks/{task_id} 查询 → 成功后下载并验证。
- 本地记录输入哈希、实际请求参数（不含密钥）、task_id、阶段、输出文件哈希、实际面数/纹理尺寸、费用。
- 超时/断网不等于失败，不能直接重复 POST。已有 task_id 先查询；未获得 ID 的不确定提交先对账或人工确认，暂停任务。
- 下载资源不附带 API Authorization；校验格式、非空内容与任务状态。
- 部分失败停在对应阶段，保存成功的原输出，禁止删除整个批次重跑。
- 生成、分件、UV 是独立步骤，不能把第一步成功当成全部完成。

## 8. 与批量贴图工作台衔接

新模型默认进入独立输出目录与待验收队列，不覆盖项目现有模型。重点检查真正正脸和局部特写，再进行贴图优化。

9 分是目标，不是让模型迎合的分数。必须保留整体、正脸、关键特写、左右侧面、纯颜色与材质证据；几何错位不能靠贴图锐化解决。

应用到项目时核对 UV、引用、文件类型、共享材质、Unity meta/GUID；若生成了新模型或重展 UV，不得只替换原贴图。批量写回必须先备份、确认映射，并支持撤回。
